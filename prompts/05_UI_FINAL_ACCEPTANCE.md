# 阶段 5：UI 对齐、回归与最终验收

此阶段不新增业务范围，目标是清零差异和占位实现。

1. 扫描整个当前 HarmonyOS 工程，重点检查 `entry/src/main/cangjie/`，
   列出并消除 TODO、stub、mock、硬编码演示数据、空 catch、永远空返回和
   未接通导航。
2. 对 `acceptance/acceptance-matrix.csv` 所有 Must 行做回归。
3. Android Studio 与 DevEco Studio 使用同一账号、网络、语言、主题、学期和业务数据，按相同操作脚本截图。
4. 对齐登录、主页、课程表、成绩、考试、工具箱、论坛、设置及所有详情页的布局、字体层级、间距、颜色、卡片、滚动、弹窗、加载/空/错误态。
5. 每次只修一个可度量差异，修后重新构建、安装、截图；保留 `acceptance/diff/` 证据。
6. 验证冷启动、清数据首登、已登录重启、弱网/断网、校园网限制、权限拒绝与旋转/不同屏宽。
7. 运行文件/符号映射审计，确认目录前缀、文件基名、类名和公开函数名尽量保持；所有例外有理由。

只有所有 Must 行为 PASS、无业务占位、构建与设备证据齐全时，才输出最终完成报告。任何受服务器、账号权限或校园网络阻塞的条目保留 `BLOCKED_EXTERNAL`，不得写“完全一致”。
